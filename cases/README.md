# Сгенерированные комплекты для проверки Сверки

`generated/` содержит 30 самостоятельных синтетических кейсов. Они созданы независимо от исходного задания в `task/data` и не используют его документы. Проверяемый договор: `26/01/01-77`, этап 3, период 01.01.2026–31.01.2026. Все организации и операции вымышлены.

## Структура одного кейса

```text
generated/00_clean/
  input/
    report.pdf             # загрузить как итоговый отчёт
    primary/               # все файлы загрузить как первичные документы
  case.json                # контекст, список входов, SHA-256, описание сценария
  expected.json            # независимый эталон желаемого поведения
  README.md                # пошаговая загрузка и ожидаемые результаты
```

В приложении нажмите «Новая проверка», перенесите договор/этап/период из `case.json`, загрузите `input/report.pdf` и все файлы из `input/primary/`. Флаг полноты берётся из `context.complete_package`; в кейсе 19 его нужно оставить снятым. JSON, README и ZIP в приложение не загружаются.

Быстрый вариант — кнопка **«Примеры проверок»** в интерфейсе. В каталоге 31 комплект: первым расположен **«Исходный комплект задания»** с пометкой «Из задания» (23 документа из `task/data`), затем 30 синтетических сценариев из этой папки. Исходные документы остаются в `task/data`; архив сгенерированных кейсов их не содержит. Выберите сценарий и нажмите **«Запустить проверку»**: документы и параметры будут заполнены автоматически. После расчёта приложение покажет сравнение с эталоном и конкретные отличия. Доступны поиск и фильтр ограничений MVP. Повреждённый XLSX из кейса 28 корректно отклоняется до создания проверки. Для появления обновлённого каталога в уже работающем приложении перезапустите сервер и обновите страницу.

Кейс 28 намеренно содержит недопустимый XLSX: ожидается отклонение загрузки первички с HTTP 400. Кейс 14 содержит повреждённый PDF: его загрузка допускается, ошибка должна быть показана при обработке, остальные файлы продолжают обрабатываться. Эти файлы специально неисправны.

**Общий прогон:** нажмите «Проверить все примеры (31)» в каталоге. Запустятся исходный комплект задания и все 30 синтетических кейсов, независимо от поискового запроса и фильтра. Вкладка «Все примеры» показывает прогресс и результат каждого сценария; окно можно закрывать, результаты последнего прогона сохраняются в БД. Повторный запуск доступен после завершения текущего. Известные ограничения считаются отдельно от новых ошибок; исправленное ограничение показывается как «Ограничение не воспроизвелось». Проверенный общий итог: **26 совпадений с эталоном, 5 ограничений MVP, 0 новых ошибок**.

`templates/` содержит девять исходных XLSX для генератора. Отдельно загружать все шаблоны в одну проверку не нужно. `catalog.json` — машиночитаемый каталог, `generated-cases.zip` — архив всех комплектов с инструкциями и эталонами.

## Сценарии

| Кейсы | Что проверяют |
|---|---|
| 00–03 | Контрольный комплект, завышение, занижение и точность копеек |
| 04–07 | Байтовый дубль, пересохранённый дубль, конфликт версий, одинаковый номер у разных контрагентов |
| 08–09 | Чужой договор и включительные границы периода |
| 10–14 | Пропущенная ведомость, отсутствующие реквизиты/сумма, неоднозначная статья, повреждённый PDF |
| 15–19 | Арифметика итога, другой договор в КФЗ, нули, отрицательная корректировка и неполный комплект |
| 20–24 | НДС и несколько денежных полей, строковые суммы Excel, пересечение периода услуг, другой договор на втором листе, ошибка формулы |
| 25–29 | Устаревший кеш Excel, PNG-скан, отсутствие строки отчёта, повреждённый XLSX и два расчёта за месяц |

Сценарии 20–24 описывают известные ограничения MVP. Их эталон задаёт желаемый результат независимо от текущей реализации. Они нужны для обнаружения проблем, поэтому ожидаемые значения не подгоняются под поведение парсера. Конкретные расхождения фиксирует прогон проверки.

Текущий результат проверки: **25 кейсов соответствуют эталону, 5 воспроизводят известные ограничения**, неожиданных ошибок нет. Полный набор проекта: **62 passed, 5 xfailed**, включая API запуска из интерфейса и независимость расчёта от эталона. Подробности — в [`VALIDATION.md`](VALIDATION.md).

## Автоматический прогон

Из корня проекта, после установки обычных тестовых зависимостей и OCR:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/validate_edge_cases.py
```

Pytest прогоняет каждый комплект через реальную multipart-загрузку API и worker, включая OCR отчёта. Известные ограничения помечены `xfail(strict=True)`: исправление реализации вызовет XPASS и потребует снять устаревшую пометку. `expected.json` приложение не читает.

Скрипт валидации создаёт отдельную временную БД в `.runtime`, сравнивает фактические значения с эталоном и сохраняет `cases/validation.local.json`. Для известных ограничений выводится отдельный результат `KNOWN_LIMITATION`; неожиданные ошибки приводят к ненулевому коду завершения. Рабочие проверки из `data/` не затрагиваются. Указанный JSON не включается в Git.

## Повторная генерация

Основной генератор использует ReportLab, Pillow, pypdf, шрифты Arial/DejaVu Sans и CLI `pdftoppm` для PNG-скана. Он копирует готовые XLSX-шаблоны, поэтому для обычной регенерации Node.js и Artifact Tool не требуются.

```powershell
python scripts/generate_edge_cases.py
python scripts/generate_edge_cases.py --only 18_credit_adjustment
```

В Codex следует запускать генератор встроенным Python из `load_workspace_dependencies`, где эти библиотеки уже доступны. В обычном окружении: `python -m pip install -r requirements-fixtures.txt` и установите Poppler, добавив `pdftoppm` в PATH. Для Linux шрифт выбирается из `/usr/share/fonts/truetype/dejavu`; альтернативный каталог задаётся через `EDGE_FONT_DIR`.

Содержимое документов воспроизводимо: нет случайных сумм и текущих дат, PDF создаются с фиксированными метаданными, ZIP — с фиксированными временными метками. Повторный запуск удаляет только файлы, перечисленные в предыдущем манифесте этого же кейса, с проверкой границ каталога. Исходный `task/data` генератор не читает и не изменяет.

Необязательный авторский шаг `scripts/generate_edge_workbooks.mjs` заново создаёт XLSX-шаблоны через встроенный `@oai/artifact-tool`. Для него нужен Codex Node runtime и ссылка `scripts/node_modules` на его пакеты. В обычном проекте достаточно готовых файлов из `templates/`. Изменение кеша формулы и повреждение OOXML выполняются отдельными намеренными мутациями отрицательных тестов.
