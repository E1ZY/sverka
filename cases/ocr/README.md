# Проверка Xiaomi OCR на кодах категорий и плохом качестве КФЗ

Этот набор проверяет распознавание изображений. Он хранится отдельно от `cases/generated`, где проверяется финансовая сверка. Новые коды не добавляются в правила бухгалтерского расчёта.

Результат реального GPU-прогона: [8 успешных кейсов и ошибка на пользовательском JPEG](VALIDATION.md).

## Файлы

| Группа | Коды | Качество |
| --- | --- | --- |
| `0400_0700` | `0400`, `0500`, `0600`, `0700` | Чёткий PNG и ухудшенный JPEG |
| `1000_1300` | `1000`, `1100`, `1200`, `1300` | Чёткий PNG и ухудшенный JPEG |
| `1300_13000` | `1300`, `13000` | Чёткий PNG и ухудшенный JPEG |
| `leading_zeros` | `0400`, `400`, `0700`, `700`, `1300`, `13000` | Чёткий PNG и ухудшенный JPEG |
| `real_kfz_reduced_quality` | Исходная КФЗ: `0200`, `0300`, `0800`, `0900` | Предоставленный пользователем JPEG 1200 × 848 |

`13000` проверяется как самостоятельный пятизначный код. Пары `0400`/`400`, `0700`/`700` и `1300`/`13000` должны оставаться разными идентификаторами.

В каждом каталоге:

- `report.png` или `report.jpeg` — полный образ карточки, который получает модель;
- `case.json` — параметры изображения, SHA-256 и границы областей таблицы;
- `expected.json` — независимые ожидаемые коды и суммы;
- `source.pdf` — векторный источник синтетической карточки, если она сгенерирована.

Во время теста модель читает только изображение. Текстовый слой `source.pdf` и содержимое `expected.json` ей не передаются. Суммы за 2025 и 2026 годы специально различаются. Распознавание кодов не означает, что приложение поддерживает эти категории в финансовой сверке: штатный профиль КФЗ по-прежнему рассчитан на исходную форму.

## Реальный запуск на GPU

Подготовьте Xiaomi OCR по основному README. Остановите приложение через Ctrl+C, чтобы на GPU была одна копия модели, и из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe scripts/validate_xiaomi_ocr.py --device cuda
```

Только предоставленный JPEG:

```powershell
.\.venv\Scripts\python.exe scripts/validate_xiaomi_ocr.py --device cuda --only real_kfz_reduced_quality
```

Проверка сохраняет в `.runtime/xiaomi-ocr-validation/`:

- ответы модели целиком (`*.txt`) и токены с уверенностью (`*.tokens.json`);
- `results.json` с фактическими кодами, суммами, ошибками, временем, устройством и версией модели;
- результат штатного извлечения КФЗ для пользовательского JPEG, если извлечение удалось.

Для синтетических карточек выполняются чтение страницы целиком и два чтения областей: заголовков с кодами и строки сумм за 2026 год. Во втором варианте проверяется точный порядок кодов и соответствующих сумм, включая итог. При чтении страницы целиком отдельно проверяется присутствие точных кодов и сумм: это само по себе не доказывает правильность всех связей между ячейками.

Для исходного JPEG дополнительно запускается неизменённый парсер КФЗ приложения. Проверяются пять основных сумм, номер договора и флаг необходимости ручной проверки. Ошибка чтения строки этапа или неправильное число не считаются успешным результатом.

Скрипт возвращает код 1, если хотя бы одна проверка распознавания не совпала с эталоном. Ожидаемые значения не исправляются под ответ модели. После завершения модель выгружается вместе с процессом; приложение можно снова запустить через `scripts/start.ps1`.

Повторно сравнить уже сохранённые ответы без загрузки модели можно с флагом `--compare-only`. Для каждого ответа проверяется SHA-256 исходного изображения; ответ от другого файла не принимается. Целая часть денежной суммы, например `13000,02`, не считается распознанным кодом `13000`.

## Повторная генерация

```powershell
.\.venv\Scripts\python.exe scripts/generate_ocr_cases.py
```

Команда пересоздаёт синтетические карточки и сохраняет уже подготовленный реальный JPEG. Чтобы заново скопировать исходный JPEG, укажите `--reduced-source` с путём к нему. Исходный файл не изменяется. Для кириллицы нужен Arial в Windows либо DejaVu Sans в Linux.

Обычные тесты проверяют целостность файлов и корректность сравнения без запуска модели:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_ocr_diagnostics.py -q
```
