# Сверка отчётности по первичным документам

Локальный MVP для проверки карточки фактических затрат КФЗ. Приложение извлекает показатели отчёта и первичных документов, исключает дубли и нерелевантные операции, рассчитывает ожидаемые суммы и показывает доказательства. В предоставленном комплекте оно обнаруживает завышение статьи 0800 на **12 500,00 ₽**.

## Быстрый запуск через Docker

Требования: Docker Engine / Docker Desktop с Compose v2, ориентировочно 4 ГБ свободной RAM. Интернет нужен для первой загрузки образов, Python/npm-зависимостей и системных языковых пакетов OCR. Документы обрабатываются локально и во внешние сервисы не передаются.

Из корня проекта:

```sh
docker compose up --build -d
```

Открыть **http://127.0.0.1:8000** и нажать **«Проверить пример»**. Swagger API: **http://127.0.0.1:8000/docs**. Первый запуск собирает интерфейс и образ приложения. После установки обработка не требует интернета.

```sh
docker compose logs -f api worker
docker compose stop
docker compose start
docker compose down
```

`stop` и `down` сохраняют документы и базу в именованных volumes. Не добавляйте `--volumes`, если данные нужно сохранить. API доступен только на loopback-интерфейсе машины. В MVP нет аутентификации: для публикации приложения необходимы отдельный защищённый шлюз и авторизация.

Compose запускает PostgreSQL 16, API и отдельный worker из одного образа. Worker начинает работу после готовности API и схемы БД. Оригиналы доступны обоим процессам через общий volume. Эталонный XLSX и README набора исключены из Docker build context.

## Запуск без Docker на Windows

Требования: Python 3.12, Node.js 20.19+ или 22+, npm. Если `python` указывает на неустановленный Windows Store alias, используйте абсолютный путь к рабочему Python.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -c constraints.txt
.\.venv\Scripts\python.exe scripts/setup_ocr.py
cd frontend
npm ci
npm run build
cd ..
.\scripts\start.ps1
```

На Windows устанавливается wheel `tesserocr`; `setup_ocr.py` скачивает открытые `eng` и `rus` веса в `.runtime/tessdata` и проверяет закреплённые SHA-256. Дополнительная системная установка Tesseract не нужна. Если политика PowerShell не позволяет запустить скрипт, используйте без изменения системной политики:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

По умолчанию используется SQLite `data/audit.db` и один встроенный worker-поток. Остановка — Ctrl+C. Для этой конфигурации запускайте только один API-процесс, без `--workers` и `--reload`. PostgreSQL используется в Docker-конфигурации; SQLAlchemy-модели общие.

На Linux для прямого запуска сначала установите `tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng`, затем Python/npm-зависимости. OCR-адаптер использует установленный CLI через pytesseract.

Для разработки интерфейса запустите API на порту 8000 и `npm run dev` из `frontend`. Vite проксирует `/api` в локальный backend.

В каталоге 31 комплект: первым идёт «Исходный комплект задания» с пометкой «Из задания» — документы из `task/data`; далее 30 сгенерированных сценариев. Кейс 28 показывает ожидаемый отказ загрузки, без запуска сверки сумм.

Если приложение уже запущено, остановите его через Ctrl+C, выполните `./scripts/start.ps1` повторно и обновите страницу. Каталог и документы доступны и в новой Docker-сборке. Эталон сравнивается с готовым результатом; расчётный пайплайн его не читает.

**Все кейсы одной кнопкой:** откройте «Тестовые кейсы» и нажмите «Прогнать все (31)». Поиск и фильтры не ограничивают общий прогон: запускается весь установленный каталог, включая исходный комплект задания. На вкладке «Общий прогон» видны прогресс, совпадения с эталонами, известные ограничения и новые ошибки; из каждой строки можно открыть соответствующую проверку. Повреждённый XLSX учитывается как успешный тест ожидаемого отказа загрузки. Окно можно закрыть, а страницу обновить: задания продолжают выполняться worker, последний прогон сохраняется в БД. Одновременный повторный запуск блокируется. Проверенный итог всего каталога: **26 совпадений, 5 известных ограничений, 0 новых ошибок**.

Инструкции и каталог сценариев: [`cases/README.md`](cases/README.md). Готовый архив: [`cases/generated-cases.zip`](cases/generated-cases.zip). Для ручной проверки создайте новую проверку с договором `26/01/01-77`, этапом 3 и периодом январь 2026 года, затем загрузите `input/report.pdf` и все файлы из `input/primary/` нужного кейса. Для кейса 19 не подтверждайте полноту комплекта.

```powershell

```

Пять кейсов (20–24) документируют ограничения, которые MVP пока не закрывает. Pytest показывает их отдельно как `xfail`, а независимый валидатор сохраняет конкретные расхождения в `cases/validation.local.json`. Кейс 28 проверяет отказ при загрузке повреждённого XLSX; кейс 14 — изоляцию ошибки повреждённого PDF при обработке.

## Пользовательские сценарии

### 1. Проверка предоставленного комплекта

Откройте «Тестовые кейсы» → «Исходный комплект задания» → «Запустить проверку». На приветственном экране также доступна кнопка «Проверить пример». Явный список из `demo/manifest.json` загружает один отчёт и 22 первичных документа. Контекст: договор `24/03/15-01`, этап 3, январь–май 2026 года, строка «3 этап, 2026 г.». Демонстрационный комплект заявлен полным для верхних статей. Названия используются только для выбора файлов демонстрации; извлечение и расчёты не зависят от имён. При запуске через каталог результат дополнительно сравнивается с `demo/expected.json` после завершения расчёта.

| Статья | В отчёте, ₽ | По источникам, ₽ | Разница, ₽ | Результат |
|---|---:|---:|---:|---|
| 0200 | 5 558 474,83 | 5 558 474,83 | 0,00 | Подтверждено |
| 0300 | 1 671 359,96 | 1 671 359,96 | 0,00 | Подтверждено |
| 0800 | 1 145 798,10 | 1 133 298,10 | +12 500,00 | Расхождение |
| 0900 | 3 204 744,51 | 3 204 744,51 | 0,00 | Подтверждено |
| Итого | 11 580 377,40 | 11 567 877,40 | +12 500,00 | Расхождение |

Учтено 19 уникальных первичных документов. Копия ADM-27, июньский акт ОРГ-0603 и акт ADM-75 другого договора исключаются с объяснением. Трудоёмкость, внутренние разбивки зарплаты/взносов и материальные затраты остаются непроверенными. Нулевое значение материальных затрат не доказывает отсутствие операций.

Откройте строку 0800: отображается расчёт из четырёх слагаемых. Нажмите на документ, чтобы увидеть исходную страницу и выделенную сумму. Для XLSX доступны лист/диапазон и исходные начисления, для DOCX — таблица/ячейка. Отдельная кнопка открывает значение в самом КФЗ. CSV содержит сводку показателей, JSON — полный результат с источниками и замечаниями.

### 2. Собственный или неполный комплект

Нажмите «Новая проверка», укажите договор, этап и период внутри одного года. Загрузите один отчёт КФЗ и первичные документы PDF/DOCX/XLSX/PNG/JPEG. В MVP профиль отчёта соответствует предоставленной 17-колоночной форме КФЗ.

Если полнота комплекта не подтверждена, система покажет подтверждённые промежуточные суммы со статусом «Недостаточно данных». Например, при отсутствии январской ведомости по зарплате статья 0200 и итог не будут помечены как ошибочные; ожидаемая полная сумма останется неизвестной. Обработка остальных файлов продолжится.

При наличии неоднозначных распознанных данных откройте документ и выберите «Уточнить данные». Можно изменить статью/сумму с обязательным основанием; API также поддерживает уточнение договора и периода. Создаётся событие аудита и новый запуск. Исходное извлечение и предыдущие результаты сохраняются. Это пользовательское уточнение, а не новое автоматическое доказательство: оно явно отмечается в результате.

## Архитектура и поток данных

```text
React → FastAPI → PostgreSQL / SQLite
                    ↓ постоянное задание Run
                  worker
                    ↓
  извлечение → нормализация → фильтрация → классификация → Decimal-сверка
                    ↓
  неизменяемый снимок результата + ссылки на фрагменты → React / JSON / CSV
```

| Модуль | Назначение |
|---|---|
| `app/main.py` | REST API, загрузки, просмотр оригиналов и страниц, экспорт, аудит уточнений |
| `app/db.py` | Case, Document, Run, Review; схема БД и сессии |
| `app/pipeline.py` | Постоянная очередь, аренда задания, прогресс, кеш извлечения и снимки запусков |
| `app/extractors.py` | PDF-текст и OCR, DOCX-таблицы, XLSX-регистры, профиль сетки КФЗ |
| `app/ocr.py` | Сменный интерфейс локального OCR; Tesseract через tesserocr или CLI |
| `app/domain.py` | Чистое расчётное ядро без доступа к файлам, БД и эталону |
| `app/rules.json` | Версия правил классификации, колонки профиля КФЗ, непроверяемые подпоказатели |
| `frontend/src` | Рабочее пространство проверок, детализация расчётов и просмотр доказательств |

Факты и доказательства хранятся структурированным JSON в Document, а операции и расчёты — в снимке Run. Каждый факт имеет источник: нормализованный прямоугольник страницы, Excel-диапазон или DOCX-адрес. Снимок содержит версии пайплайна/правил, контекст, хеши файлов и применённые уточнения. Денежные значения сериализуются строками, расчёт выполняется через Decimal с ROUND_HALF_UP до копейки. Дельта — отчёт минус ожидаемое значение.

Дубли выявляются по SHA-256 и реквизитам: номер, дата, договор, контрагент, сумма. Конфликтующие версии с разными суммами исключаются из подтверждённого агрегата до проверки. Для зарплаты и взносов контролируется наличие единственного расчёта на каждый месяц. Пересечение периода не распределяется пропорционально автоматически.

Отсутствующие данные не превращаются в нули. Ошибка чтения/неоднозначная связь консервативно блокирует полное подтверждение агрегатов, поскольку нераспознанный документ может относиться к любой статье. В итоговом заключении всегда указываются границы проверки.

Тяжёлое извлечение выполняет worker. В PostgreSQL задание выбирается через `FOR UPDATE SKIP LOCKED`; локальный SQLite рассчитан на одного worker. Аренда обновляется при переходе к документу, истекает через 10 минут. Задание после прерывания подбирается повторно, максимум три попытки. Успешные извлечения кешируются; повторный запуск пересчитывает результат из фактов и снимка уточнений. Таблицы создаются автоматически; для последующих изменений схемы понадобятся миграции.

## Настройки

Переменные окружения читаются процессом при старте. Для прямого запуска `.env` автоматически не загружается: задайте переменные в shell. Compose читает `.env`; образец — `.env.example`.

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `DATABASE_URL` | SQLite `data/audit.db`; Compose задаёт PostgreSQL |
| `DATA_DIR` | `data/`; оригиналы и локальная БД |
| `DEMO_DIR` | `task/data`; в контейнере `/demo` |
| `FIXTURES_DIR` | `cases/`; каталог, входные документы и эталоны синтетических кейсов |
| `EMBED_WORKER` | `true` локально; `false` для отдельного worker |
| `TESSDATA_PREFIX` | `.runtime/tessdata` для Windows tesserocr; Linux CLI использует системные модели |
| `TESSERACT_CMD` | Необязательный путь к CLI Tesseract |
| `POSTGRES_PASSWORD` | Локальный пароль Compose; при изменении используйте URL-safe символы |

Ограничения загрузки: 25 МБ на файл, 100 файлов на проверку, 50 страниц на PDF, распакованный DOCX/XLSX до 100 МБ. Ошибки файлов показываются отдельно. Внешние сервисы, API-ключи, GPU и облачная LLM не требуются.

## Границы MVP

Профиль КФЗ поддерживает данную табличную форму и одну выбранную годовую строку на первой странице. Координаты сетки определяются по изображению, суммы не зашиты в код. Произвольные формы, повёрнутые/перспективно искажённые и низкокачественные сканы требуют дополнительных профилей и предобработки.

XLSX-парсер поддерживает структуры ведомостей/взносов этого набора. Он складывает исходные начисления и не использует пустой или устаревший кеш итоговой формулы. Универсальное вычисление Excel-формул не реализовано. Текстовые документы рассматриваются как одна денежная операция; документы с несколькими различными суммами требуют уточнения. Классификация основана на прозрачных смысловых правилах, сложные случаи получают статус проверки.

Следующие расширения: построчная модель многооперационных актов и УПД, регистры полноты, дополнительные профили КФЗ, PaddleOCR/VLM-адаптер с оценкой качества, авторизация и разграничение доступа, миграции схемы, объектное хранилище. Полнота комплектов и профессиональная оценка бухгалтерского учёта остаются за пользователем.
